# Feature Specification: 本地内容规模与检索能力升级

**Created**: 2026-10-21
**Status**: Draft
**Input**: 用户要求完成 `TODO.md` 中 P0-3 与 P1 阶段的第一批：P0-3 取消 1000 篇硬上限 + 归档策略、P1-1 全文检索、P1-3 单源级设置。

## Overview

当前应用把文章本地缓存限制在 1000 篇，超出即删除未收藏文章；搜索仅在内存中对已加载列表做线性匹配；抓取、全文、保留、通知等策略只有全局开关。本次升级让用户**长期保留阅读历史**、**在全部历史中快速检索**，并能**按订阅源分别控制抓取与保留行为**，从而在不引入账号与云端的前提下，使本地体验对齐主流 RSS 阅读器。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 历史文章不再被自动删除 (Priority: P1)

用户长期订阅几十个源、累计阅读上万篇。他需要历史文章一直可查、可读，而不是被系统在后台悄悄清掉。

**Why this priority**: 数据丢失是最高等级的信任问题；也是全文检索能覆盖全部历史的前提。

**Independent Test**: 构造超过 5000 篇历史数据，执行抓取与清理任务后，早期文章仍能在列表中打开、能被搜索命中。

**Acceptance Scenarios**:

1. **Given** 用户从未修改保留策略，**When** 本地文章累计超过 1000 篇，**Then** 不删除任何未收藏文章，全部历史保留。
2. **Given** 用户把保留策略设为「保留 90 天」，**When** 后台清理执行，**Then** 仅删除 90 天前且未收藏、未加稍后读、无高亮的文章。
3. **Given** 清理删除了若干文章，**When** 用户在 7 天内进入「最近删除」，**Then** 可以恢复这些文章及其已读/收藏状态。
4. **Given** 用户进入「存储与保留」页，**When** 页面加载完成，**Then** 展示总占用、按源占用、预计可清理条数，且与实际库内数据一致。

---

### User Story 2 - 在全部历史中全文检索 (Priority: P1)

用户记得某篇文章提到过某个概念，但记不清来源与标题。他需要一次搜索覆盖标题、摘要、正文、作者，并能按来源/状态/时间过滤。

**Why this priority**: 搜索是长文阅读器的核心复访路径；当前实现只能在当前列表内匹配，数据量一大就不可用。

**Independent Test**: 导入 10000 篇文章后，搜索一个只出现在正文中的中文关键词，能在 300ms 内返回结果并定位到正文位置。

**Acceptance Scenarios**:

1. **Given** 本地有 10000 篇文章，**When** 用户输入关键词，**Then** 首屏结果在 300ms 内出现，且包含只在正文中出现的命中项。
2. **Given** 用户输入 `from:少数派 is:unread`，**When** 执行搜索，**Then** 结果仅包含该来源且未读的文章。
3. **Given** 搜索结果中的某篇文章，**When** 用户点击结果，**Then** 打开文章并高亮命中片段、滚动到首个命中位置。
4. **Given** 用户完成过一次搜索，**When** 再次打开搜索页，**Then** 可以看到最近搜索历史并可一键复搜。
5. **Given** 数据升级或索引损坏，**When** 用户触发「重建索引」，**Then** 索引在后台重建完成，期间阅读与抓取不中断。

---

### User Story 3 - 按订阅源控制抓取与保留 (Priority: P2)

用户订阅了大量更新频繁的源，希望个别源降低抓取频率、关闭通知、只保留最近内容，而不影响其他源。

**Why this priority**: 单源控制是规模化的必要条件，但可以独立于搜索与保留策略交付。

**Independent Test**: 对某个源关闭抓取并设置保留 30 天，验证该源不再产生新文章与通知，历史按策略清理，其他源不受影响。

**Acceptance Scenarios**:

1. **Given** 用户在某源设置中关闭「启用抓取」，**When** 前台刷新与后台任务执行，**Then** 该源不发起网络请求、不产生新文章、不发送通知，历史文章仍可读。
2. **Given** 用户为某源单独设置抓取间隔 6 小时，**When** 距离上次抓取不足 6 小时，**Then** 自动刷新跳过该源，手动刷新仍可强制抓取。
3. **Given** 用户为某源单独设置保留 30 天，**When** 清理执行，**Then** 该源仅保留 30 天内文章，其他源遵循各自/全局策略。
4. **Given** 某源连续抓取失败，**When** 用户查看订阅详情，**Then** 能看到最后成功时间、连续失败次数，并可手动重试。
5. **Given** 用户把某源设置改回「跟随全局」，**When** 后续抓取与清理执行，**Then** 该源行为与全局设置完全一致。

---

### Edge Cases

- 保留策略设为「永久」时，清理任务不删除任何文章，仅统计占用。
- 清理与搜索/阅读同时进行时，不得删除正在阅读或已加入撤销队列的文章。
- 搜索关键词为空、仅含空白、或仅含语法标记（如 `from:` 无值）时，应视为空查询并给出引导，不报错。
- 搜索包含 SQL 特殊字符（引号、`%`、`_`、`*`）时不得导致查询失败或注入。
- 中文、日文、韩文等无空格语言必须能被命中（分词或二元组/前缀兜底）。
- 单源设置为非法值（负数、未知枚举、超大天数）时，回退到全局或默认值。
- 源被删除后，其单源设置与健康状态一并清除；其文章按现有删除源逻辑处理。
- 数据库升级失败时，应用应以「无缓存」降级启动，而不是崩溃。
- 索引重建期间用户继续搜索，应返回可用的旧索引结果或明确提示「索引重建中」。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 默认保留全部历史文章，不再因固定条数上限删除数据。
- **FR-002**: 系统 MUST 提供保留策略配置：永久 / 30 天 / 90 天 / 365 天 / 仅保留未读与收藏。
- **FR-003**: 系统 MUST 在清理时永久排除收藏、稍后读、含高亮的文章。
- **FR-004**: 系统 MUST 在清理前给出影响条数预览，并要求用户确认。
- **FR-005**: 系统 MUST 支持清理后 7 天内恢复被删文章及其阅读状态。
- **FR-006**: 系统 MUST 提供存储管理视图：总占用、按源占用、可清理条数、立即清理入口。
- **FR-007**: 系统 MUST 提供覆盖标题、摘要、正文、作者的本地全文检索。
- **FR-008**: 系统 MUST 将检索下沉到本地数据库索引，支持分页并保证 1 万篇规模下首屏响应可接受。
- **FR-009**: 系统 MUST 支持检索语法：来源、已读状态、收藏状态、时间范围。
- **FR-010**: 系统 MUST 记录并展示最近搜索历史，支持清空。
- **FR-011**: 系统 MUST 在检索结果中高亮命中词，并可跳转到正文对应位置。
- **FR-012**: 系统 MUST 提供索引重建能力，且重建不阻塞阅读与抓取。
- **FR-013**: 系统 MUST 支持单源覆盖设置：启用抓取、抓取间隔、全文策略、保留天数、通知、滚动即已读。
- **FR-014**: 系统 MUST 保证停用源不参与自动抓取、后台任务与通知，但历史文章保留。
- **FR-015**: 系统 MUST 按源判断抓取到期时间；手动刷新 MUST 可强制抓取到期或停用外的源。
- **FR-016**: 系统 MUST 在订阅详情中展示源健康状态：最后成功时间、连续失败次数、最近错误。
- **FR-017**: 系统 MUST 对所有新增设置做归一与脏值降级，并持久化。
- **FR-018**: 系统 MUST 为所有新增界面提供简体中文与英文文案。

### Key Entities *(include if feature involves data)*

- **保留策略（Retention Policy）**：作用于全部或单个订阅源的删除规则，含模式（永久/按天数/仅未读与收藏）与天数。
- **订阅源设置（Feed Preferences）**：每个源可覆盖的抓取与保留配置，以及「跟随全局」标记。
- **源健康状态（Feed Health）**：最后成功时间、连续失败次数、最近错误信息。
- **检索查询（Search Query）**：关键词与过滤条件（来源、已读、收藏、时间范围）、排序方式。
- **检索历史（Search History）**：最近查询记录与时间。
- **回收站条目（Trash Item）**：被清理文章的标识、删除时间与可恢复的阅读状态。
- **本地检索索引（Search Index）**：标题、摘要、正文、作者的检索结构，可重建。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 累计 10000 篇文章时，90% 的搜索在 300ms 内返回首屏结果。
- **SC-002**: 累计 10000 篇文章时，应用冷启动到列表可交互不超过 3 秒（不因检索索引显著变慢）。
- **SC-003**: 100% 的收藏、稍后读、含高亮文章的清理保护生效（自动化用例覆盖）。
- **SC-004**: 被误清理的文章在 7 天内 100% 可恢复。
- **SC-005**: 单源设置生效后，停用源在 24 小时内产生的新文章与通知数量为 0。
- **SC-006**: 存储管理页展示的条数与占用，与数据库实际值误差为 0。
- **SC-007**: 中文、英文、日文关键词搜索均能返回命中结果（每种语言至少 3 个用例）。

## Assumptions

- 本轮不引入账号、云同步与第三方服务，全部能力基于本地数据库与偏好设置。
- 翻译（P1-4）、音视频 enclosure（P1-5）、标签/规则（P1-2）、分享扩展（P1-6）不在本轮范围。
- 现有「归档规则」（已读且超过 N 天不进主列表）与本次「保留策略」（是否删除）是两套独立机制，互不替代。
- 本地数据库支持全文检索与多语言分词；不支持时以可用的降级分词方式实现，保证功能可用。
- 用户设备存储充足；容量不足时优先提示用户调整保留策略，而不是静默删除。
- 文章标识在升级前后保持稳定，避免升级导致已读/收藏状态丢失。
- 现有纯状态管理 V2 约束、HDS 组件约束与构建环境限制继续有效。
