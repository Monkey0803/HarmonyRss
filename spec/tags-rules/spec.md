# Feature Specification: 标签与智能文件夹

**Created**: 2026-10-22
**Status**: Draft

## Overview

在现有「订阅源分组 + 搜索」之外，给文章增加**多标签**与**可保存的检索条件（智能文件夹）**，
让用户能按主题而非按来源组织阅读。两者都复用现有本地数据库与检索链路，不引入账号或云端。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 给文章打标签并按标签聚合 (Priority: P1)

用户读到一个好文章，想归类到「AI」「设计」等主题下，之后能一键只看某个主题的全部文章。

**Why this priority**: 标签是内容组织的最小闭环，独立可用，且是智能文件夹的前置。

**Independent Test**: 新建标签 → 单篇打标签 → 标签页能看到该文章；批量给多篇打同一标签；重命名/删除标签后关联正确。

**Acceptance Scenarios**:

1. **Given** 用户在某篇文章详情页，**When** 打开标签选择器并勾选「AI」，**Then** 该文章立即出现在「AI」标签页，标签计数 +1。
2. **Given** 用户在首页多选模式选中 20 篇，**When** 选择「打标签 → 设计」，**Then** 20 篇全部关联「设计」，计数 +20。
3. **Given** 标签「AI」下有文章，**When** 用户把标签重命名为「人工智能」，**Then** 所有关联文章的标签显示同步更新，计数不变。
4. **Given** 标签「AI」下有文章，**When** 用户删除该标签并确认，**Then** 标签消失、文章保留，文章的已读/收藏/内容不受影响。
5. **Given** 用户同时选中「AI」与「设计」两个标签，**When** 查看结果，**Then** 只显示**同时具备**两个标签的文章。

---

### User Story 2 - 保存检索条件为智能文件夹 (Priority: P1)

用户常用「未读 + 来源：少数派 + 关键词 AI」这类组合查询，希望保存下来一键进入，而不是每次重新输入。

**Why this priority**: 复用已交付的检索能力，成本低、复访价值高。

**Independent Test**: 新建智能文件夹（名称 + 查询串），点击后结果与在搜索页输入同一查询完全一致；编辑查询后结果随之变化。

**Acceptance Scenarios**:

1. **Given** 用户在搜索页输入 `from:少数派 is:unread AI` 并得到结果，**When** 选择「保存为智能文件夹」并命名，**Then** 订阅页出现该智能文件夹。
2. **Given** 已保存的智能文件夹，**When** 用户点击进入，**Then** 使用同一检索链路（含中文索引）返回相同结果。
3. **Given** 智能文件夹的查询串，**When** 用户编辑为另一组条件并保存，**Then** 下次打开按新条件返回结果。
4. **Given** 用户输入空查询或只有空白，**When** 尝试保存，**Then** 保存被拒绝并给出明确提示。
5. **Given** 多个智能文件夹，**When** 用户上移/下移排序，**Then** 顺序持久化，重启后保持不变。

---

### User Story 3 - 组织入口与状态可见 (Priority: P2)

用户需要知道标签和智能文件夹在哪里、各有多少内容，并在阅读时看到当前文章的标签。

**Why this priority**: 入口与状态决定功能可发现性，但不影响核心数据链路。

**Independent Test**: 订阅页顶部出现「标签」「智能文件夹」入口；详情页显示已有标签；计数随操作实时变化。

**Acceptance Scenarios**:

1. **Given** 用户进入订阅页，**When** 页面上半部分加载完成，**Then** 能看到「标签」「智能文件夹」两个入口及标签数量。
2. **Given** 文章已有 2 个标签，**When** 打开详情页，**Then** 标题/正文区域能看到这 2 个标签并可快速移除。
3. **Given** 用户删除某标签，**When** 返回订阅页，**Then** 标签入口的数量同步更新。

---

### Edge Cases

- 标签名全为空白、超长（>32 字符）或与已有标签仅大小写不同 → 归一后拒绝或复用已有标签。
- 一篇文可挂多个标签；同一标签重复添加不产生重复关联。
- 文章被删除或被保留策略清理/恢复时，其标签关联同步清理/恢复。
- 删除标签不删除文章；恢复文章时若标签已删除，则不恢复失效关联。
- 智能文件夹查询串包含非法日期、未知 `is:` 值、超长文本 → 按现有搜索解析规则降级，不报错。
- 智能文件夹数量很多时（>50），列表仍可滚动与排序。
- 数据库升级失败时不删库，标签/智能文件夹降级为不可用，阅读与检索不受影响。
- 升级后已有文章的已读/收藏/标签（若有旧数据）不得丢失。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持创建、重命名、删除标签；名称需归一（去首尾空白、长度上限 32、大小写不敏感去重）。
- **FR-002**: 系统 MUST 支持单篇文章添加/移除标签，并即时反映到标签计数。
- **FR-003**: 系统 MUST 支持在首页多选模式下批量添加标签。
- **FR-004**: 系统 MUST 提供标签筛选视图，并支持同时选择多个标签（AND 语义）。
- **FR-005**: 系统 MUST 在标签列表展示每个标签的文章数量，并按名称排序。
- **FR-006**: 系统 MUST 支持创建、编辑、删除智能文件夹（名称 + 查询串）。
- **FR-007**: 智能文件夹的查询串 MUST 复用现有检索语法（关键词 / `from:` / `is:` / `after:` / `before:` / 引号短语），并拒绝空查询。
- **FR-008**: 打开智能文件夹 MUST 走与搜索页相同的检索链路（含中文二元组索引），结果与同条件搜索一致。
- **FR-009**: 系统 MUST 支持智能文件夹的手动排序并持久化。
- **FR-010**: 系统 MUST 在订阅页提供「标签」「智能文件夹」入口，并展示标签总数/各标签文章数。
- **FR-011**: 文章详情页 MUST 展示当前文章的标签，并支持添加/移除。
- **FR-012**: 文章删除、清理、恢复时 MUST 同步维护标签关联。
- **FR-013**: 所有新增界面 MUST 提供简体中文与英文文案。
- **FR-014**: 数据库 MUST 通过版本化迁移新增标签与智能文件夹结构，升级失败不丢数据、不崩溃。
- **FR-015**: 标签与智能文件夹数量 MUST 有软上限保护（标签 100、智能文件夹 50），超限时提示。

### Key Entities *(include if feature involves data)*

- **标签（Tag）**：名称（唯一、归一后）、创建时间；与文章多对多。
- **文章标签关联（ArticleTag）**：文章 id + 标签 id，联合唯一；随文章删除/恢复同步。
- **智能文件夹（SmartFolder）**：名称、查询串、排序位、创建/更新时间。
- **标签计数（TagCount）**：每个标签关联的文章数量（查询派生，不单独存）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从文章详情完成一次打标签不超过 3 次点击。
- **SC-002**: 智能文件夹结果与同条件搜索的结果一致率为 100%（固定用例集回归）。
- **SC-003**: 2 万篇文章、50 个标签下，标签筛选首屏 < 300ms。
- **SC-004**: 删除标签后，0 篇文章丢失，已读/收藏状态不变。
- **SC-005**: 批量给 100 篇文章打同一标签 < 2 秒完成。
- **SC-006**: 从旧版本升级后，已有文章、已读、收藏、高亮 0 丢失。
- **SC-007**: 标签与智能文件夹在应用重启后 100% 保留。

## Assumptions

- 本轮只做**标签 + 智能文件夹**；规则引擎与跨源去重留到第二批，已确认的后续口径为「规则仅对新文章生效」「去重按 URL 归一化或同标题 ±24h 合并展示」。
- 标签 v1 不支持层级与颜色，只支持名称。
- 智能文件夹复用搜索语法原始字符串，不新增 DSL；不引入「保存当前列表筛选」的隐式规则。
- 多标签筛选采用 AND 语义（同时具备）。
- 标签与智能文件夹仅本地存储；多端同步留到 P0-1/P0-2。
- 智能文件夹列表不展示实时结果数，避免每次进入都执行全量查询。
- 现有纯状态管理 V2、HDS 组件与构建约束继续有效。
