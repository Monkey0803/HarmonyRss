# Feature Specification: 跨源去重

**Created**: 2026-10-22
**Status**: Draft
**Input**: `TODO.md` P1-2 剩余项。用户已确认：入库时固化、先入库者为主条、组内状态同步、设置页总开关默认开启。

## Overview

同一篇文章经常被多个订阅源同时收录（不同站点转载、聚合源与原文源）。本功能在文章入库时判定重复，
把后续重复项挂到先入库的「主条」下：列表与计数只出现一次，但保留全部来源出处；
已读/收藏/标签在组内同步，删除或清理主条时自动提升新主条，保证不丢文章。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 不同源的同篇文章只出现一次 (Priority: P1)

用户同时订阅了少数派与 Hacker News，同一篇链接被两边收录，希望在列表里只看到一次。

**Why this priority**: 重复内容是跨源订阅最影响阅读效率的问题。

**Independent Test**: 构造两个源收录同一 URL 与「同标题 ±24h」的文章，入库后列表只出现一条，来源数为 2。

**Acceptance Scenarios**:

1. **Given** 源 A 已有一篇文章，**When** 源 B 抓取到 URL 归一化后相同的文章，**Then** 列表只显示 A 的那条，并标记「2 个来源」。
2. **Given** 两源文章标题归一化后相同且发布时间相差 ≤24 小时但链接不同，**When** 后者入库，**Then** 同样合并。
3. **Given** 两篇标题相同但发布时间相差 >24 小时，**When** 入库，**Then** 不合并，各自独立展示。
4. **Given** 同一源内重复条目，**When** 入库，**Then** 按既有 id 去重逻辑处理，不进入跨源合并。
5. **Given** 用户在设置中关闭去重，**When** 新文章入库，**Then** 不再合并；已有合并组保持现状。

---

### User Story 2 - 来源出处可见 (Priority: P1)

用户想知道这篇合并文章还来自哪些源，并能打开对应链接。

**Independent Test**: 列表行显示来源数；详情页展示全部来源（源名 + 原文链接），可分别打开。

**Acceptance Scenarios**:

1. **Given** 一条合并了 3 个来源的文章，**When** 查看列表，**Then** 行上显示「3 个来源」标识。
2. **Given** 打开该文章详情，**When** 查看来源区，**Then** 能看到 3 个来源的源名，并可逐条打开对应链接。
3. **Given** 只有 1 个来源的普通文章，**When** 查看列表与详情，**Then** 不显示来源标识/来源区，界面与现状一致。

---

### User Story 3 - 状态与生命周期在组内一致 (Priority: P1)

用户在主条上标已读/收藏/打标签后，不希望同组其它来源仍显示未读；删除或清理主条也不能把文章弄丢。

**Independent Test**: 主条标已读 → 组内全部已读且远端回写覆盖所有映射；删除主条后组内自动出现新主条。

**Acceptance Scenarios**:

1. **Given** 组内有 3 篇，**When** 用户把主条标为已读，**Then** 3 篇都为已读，未读数只减 1。
2. **Given** 组内某篇来自远端账号，**When** 主条状态变化，**Then** 组内所有有远端映射的文章都进入待同步队列。
3. **Given** 组内有 3 篇，**When** 用户给主条打标签，**Then** 3 篇都关联该标签（后续提升主条时不丢标签）。
4. **Given** 主条被删除或按保留策略清理，**When** 组内仍有其它文章，**Then** 自动提升其中最早入库的一篇为新主条，列表继续可见。
5. **Given** 组内只剩主条，**When** 删除主条，**Then** 组随之消失，行为与普通文章一致。

---

### Edge Cases

- URL 带跟踪参数（utm_*、fbclid、gclid）、大小写 host、末尾斜杠、锚点。
- 标题带全角/半角标点、空格、大小写差异。
- 发布时间缺失（0）时以入库时间为准参与 ±24h 判断。
- 一篇文章同时命中 URL 规则与标题规则 → 只合并一次（取先命中的主条）。
- 同一篇文章第三次、第四次入库（同步重复）→ 不产生新的主条或重复挂靠。
- 主条被隐藏（规则）时，整组都不进主列表。
- 主条被规则打标签/标记已读时，组内同步。
- 远端同步与本地抓取同时插入同一文章（并发）→ 最终只有一个主条。
- 关闭去重时已有组保持不变；重新开启后新文章可并入已有主条。
- 标题为空、链接为空（极端 feed）→ 不参与合并。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在文章入库时判定跨源重复，并只对**不同订阅源**之间生效。
- **FR-002**: URL 判定 MUST 先归一化：忽略 scheme/host 大小写、去锚点、去常见跟踪参数、去末尾斜杠。
- **FR-003**: 标题判定 MUST 先归一化：小写、去空白与标点；要求发布时间相差 ≤24 小时（缺失时用入库时间）。
- **FR-004**: 重复项 MUST 记录其主条，并从主列表、未读数、分组计数、标签列表、搜索结果中排除。
- **FR-005**: 主条 MUST 展示来源总数，详情页 MUST 列出全部来源（源名 + 链接）。
- **FR-006**: 已读、收藏、标签、隐藏 MUST 在组内同步；远端状态回写 MUST 覆盖组内所有有映射的文章。
- **FR-007**: 主条被删除或清理时，MUST 自动提升组内最早入库的剩余文章为新主条；无剩余时组消失。
- **FR-008**: 系统 MUST 提供去重总开关，默认开启；关闭后仅影响新入库文章。
- **FR-009**: 升级后 MUST 为已有文章补齐 URL/标题归一化键，使其也能作为新文章的合并候选。
- **FR-010**: 同一源内的重复 MUST 继续由既有 id 去重处理，不进入跨源逻辑。
- **FR-011**: 去重判定失败 MUST 不影响文章入库（降级为独立文章）。
- **FR-012**: 所有新增界面文案 MUST 提供简体中文与英文。
- **FR-013**: 规则引擎动作 MUST 作用于合并组（打标签/已读/收藏/隐藏同步到全部成员）。
- **FR-014**: 去重 MUST NOT 修改或删除任何文章内容，只建立挂靠关系。

### Key Entities *(include if feature involves data)*

- **主条（Canonical Article）**：组内最早入库的文章，承担展示与计数。
- **重复项（Duplicate Article）**：记录主条 id，保留自身来源与远端映射，不参与列表。
- **归一化键（Normalized Keys）**：URL 键与标题键，用于入库时匹配。
- **来源组（Source Group）**：主条 + 全部重复项，状态同步与生命周期提升的作用单位。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同一 URL 被两个源收录时，列表出现次数为 1，来源数为 2。
- **SC-002**: 重复入库/重复同步 10 次后，组数量与成员关系稳定（无新增重复组、无重复挂靠）。
- **SC-003**: 主条状态变更后，组内状态一致率 100%；未读数只按主条计。
- **SC-004**: 删除/清理主条后，组内文章丢失率 0%（至少保留一篇）。
- **SC-005**: 去重开关关闭后，新文章合并数 0；已有组合并关系保持不变。
- **SC-006**: 升级后已有文章补键成功率 ≥99%，不因补键失败影响启动（可后台重试）。
- **SC-007**: 2 万篇文章规模下，单篇入库的去重判定额外耗时 < 50ms。

## Assumptions

- 本轮只做入库时固化与升级补键，不提供「历史全量重建/手动拆分合并」入口（后续批次）。
- 主条一旦确定不因新文章到达而切换；只有主条被删除/清理时才提升。
- 组内状态同步为「并集」：任一成员已读/收藏即全组已读/收藏，标签取并集。
- 隐藏作用在整组：主条隐藏则组内全部从主列表排除。
- 合并只影响展示与状态，不修改文章内容、不改变远端数据。
- 同一源内重复仍由现有 id（源 + 链接）去重处理。
- 现有纯状态管理 V2、HDS 约束、schema 版本化迁移继续有效。
