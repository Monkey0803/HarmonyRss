# Feature Specification: 本地规则引擎

**Created**: 2026-10-22
**Status**: Draft
**Input**: `TODO.md` P1-2 第二批中的规则引擎部分。用户已确认：本轮只做规则，跨源去重下一批；动作为「已读 / 收藏 / 打标签 / 隐藏」；多条规则全部按优先级执行；对所有新文章（本地抓取 + 远端同步）生效。

## Overview

让用户用几条本地规则自动处理新文章：命中关键词就标记已读、收藏、自动打标签或隐藏。
规则只影响**新入库**文章，不改历史；隐藏只是从主列表移除，文章仍可检索、可恢复，不会被删除。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 创建与管理规则 (Priority: P1)

用户订阅了一个高频源，想自动把「广告」「招聘」类文章隐藏，把「AI」相关文章打上标签并标记已读。

**Why this priority**: 没有可管理的规则入口，引擎无从配置与调整。

**Independent Test**: 新建规则、启用/停用、调整优先级、编辑、删除；试运行只统计不修改文章。

**Acceptance Scenarios**:

1. **Given** 用户在「规则」页点击新建，**When** 填写名称、关键词、字段与动作并保存，**Then** 规则出现在列表且默认启用。
2. **Given** 已有规则，**When** 用户关闭启用开关，**Then** 后续新文章不再被该规则处理，历史结果不变。
3. **Given** 两条规则有先后顺序，**When** 用户上移/下移，**Then** 顺序持久化，重启后保持。
4. **Given** 用户点击「试运行」，**When** 执行完成，**Then** 显示「最近 N 篇中命中 M 篇」，且没有任何文章被修改。
5. **Given** 关键词为空或规则名称为空，**When** 保存，**Then** 保存被拒绝并给出明确提示。

---

### User Story 2 - 新文章自动执行规则 (Priority: P1)

用户希望新文章一进来就按规则处理，不需要手动逐篇操作。

**Why this priority**: 这是规则引擎的核心价值。

**Independent Test**: 新建「AI → 打标签 + 标记已读」规则，构造一条包含 AI 的新文章，入库后自动命中。

**Acceptance Scenarios**:

1. **Given** 规则「标题含 AI → 打标签 AI + 标记已读」，**When** 本地抓取到一篇标题含 AI 的新文章，**Then** 自动打上 AI 标签且为已读，标签计数同步增加。
2. **Given** 规则「正文含 招聘 → 收藏」，**When** 远端同步进来一篇正文含「招聘」的新文章，**Then** 同样自动收藏（本地抓取与远端同步都生效）。
3. **Given** 同一篇新文章同时命中「打标签 A」与「打标签 B」两条规则，**When** 入库，**Then** 两个标签都生效（规则全部执行）。
4. **Given** 同一篇文章多次同步（重复入库被忽略），**When** 重复执行，**Then** 不产生重复标签关联、不重复计数。
5. **Given** 规则命中并隐藏文章，**When** 用户回到主列表，**Then** 该文章不出现，但「已隐藏」列表与检索仍能找到。

---

### User Story 3 - 隐藏与可观测 (Priority: P2)

用户需要知道规则到底做了什么，并能找回被隐藏的文章。

**Independent Test**: 规则列表显示累计命中次数与最后命中时间；已隐藏列表可打开、可取消隐藏。

**Acceptance Scenarios**:

1. **Given** 规则运行过，**When** 打开规则页，**Then** 能看到每条规则的累计命中次数与最后命中时间。
2. **Given** 有被隐藏的文章，**When** 打开「已隐藏」列表，**Then** 可看到全部被隐藏文章并打开阅读。
3. **Given** 用户在已隐藏列表取消隐藏，**When** 返回主列表，**Then** 该文章重新出现。
4. **Given** 规则引用了已删除的订阅源，**When** 编辑规则，**Then** 提示来源已失效并要求重新选择。

---

### Edge Cases

- 关键词包含空格、标点、大小写、全角/半角；匹配为大小写不敏感的包含匹配。
- 正文很长（>100KB）时只匹配前 20K 字符，避免拖慢入库。
- 规则数量很多（接近上限 100）且一次入库 200 篇时的耗时。
- 规则命中已读文章（新入库即为已读）时的重复动作。
- 远端同步批量插入与规则执行的中途失败：文章已入库、动作部分完成。
- 规则被删除 / 停用后，已产生的标签、已读、收藏、隐藏状态保留。
- 隐藏文章参与保留策略清理与搜索，与普通文章一致。
- 标签被删除后，规则的「添加标签」动作失效（跳过该动作并记录）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持创建、编辑、删除、启用/停用规则，并支持手动排序。
- **FR-002**: 规则 MUST 包含：名称、启用状态、关键词（多个，AND）、匹配字段（标题/摘要/正文/作者，可多选）、来源范围（全部或指定源）、动作（已读/收藏/添加标签/隐藏，可多选）、优先级。
- **FR-003**: 系统 MUST 对所有新入库文章执行规则（本地抓取与远端同步），历史文章不回溯。
- **FR-004**: 一篇文章命中多条规则时 MUST 按优先级全部执行；动作只增不减（不会取消已读/收藏，不会移除他人添加的标签）。
- **FR-005**: 添加标签动作 MUST 幂等，重复执行不产生重复关联。
- **FR-006**: 隐藏 MUST 只影响主列表展示；被隐藏文章 MUST 仍可检索、可打开、可取消隐藏，且不参与删除。
- **FR-007**: 系统 MUST 提供规则试运行：只统计命中数量，不修改任何文章。
- **FR-008**: 系统 MUST 记录每条规则的累计命中次数与最后命中时间。
- **FR-009**: 规则 MUST 有数量上限（100）与关键词数量上限（每条 10 个），超限提示。
- **FR-010**: 匹配 MUST 对大小写不敏感；正文匹配 MUST 限制在固定字符数以内以保证入库性能。
- **FR-011**: 规则执行失败 MUST 不影响文章入库与阅读；失败原因可诊断。
- **FR-012**: 所有新增界面与错误文案 MUST 提供简体中文与英文。
- **FR-013**: 数据库 MUST 通过版本化迁移新增规则表与文章隐藏标记，升级失败不丢数据。
- **FR-014**: 规则引用的来源或标签被删除时 MUST 安全跳过对应动作。

### Key Entities *(include if feature involves data)*

- **规则（Rule）**：名称、启用、优先级、关键词集合、匹配字段集合、来源范围、动作集合、累计命中次数、最后命中时间。
- **规则条件（RuleCondition）**：关键词与字段的组合（同一规则内 AND）。
- **规则动作（RuleAction）**：已读 / 收藏 / 添加标签 / 隐藏。
- **隐藏标记（Hidden Flag）**：文章级布尔值，参与主列表过滤，不影响删除与检索。
- **规则命中统计（RuleStats）**：每条规则的累计命中与最近命中时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100 条规则 × 200 篇新文章，规则匹配耗时 < 500ms（不含落库）。
- **SC-002**: 重复入库/重复同步 10 次后，标签关联重复数 0。
- **SC-003**: 被隐藏文章在主列表出现率 0%；在已隐藏列表与检索中可 100% 找到。
- **SC-004**: 规则试运行前后，文章状态变更数 0。
- **SC-005**: 规则执行失败时，文章入库成功率 100%（失败只影响动作）。
- **SC-006**: 从旧版本升级后，已有文章、已读、收藏、标签、隐藏状态 0 丢失。
- **SC-007**: 规则配置在重启后 100% 保留。

## Assumptions

- 本轮只做规则引擎；跨源去重留到下一批。
- 匹配为关键词包含（大小写不敏感），不支持正则；同一规则内多关键词为 AND，多条规则之间按优先级全部执行。
- 动作只做「加」不做「减」：不会把已读改回未读、不会取消收藏、不会移除标签。
- 不提供历史回溯执行；「试运行」只读统计（默认统计最近 500 篇）。
- 隐藏不等于删除，隐藏文章仍受保留策略与检索影响。
- 规则在文章入库后同步执行；动作失败不回滚文章。
- 现有纯状态管理 V2、HDS 约束、schema 版本化迁移继续有效。
