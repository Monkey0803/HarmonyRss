# Feature Specification: FreshRSS 兼容服务接入（Google Reader API）

**Created**: 2026-10-22
**Status**: Draft
**Input**: `TODO.md` P0-2 第一版。用户已确认：仅支持 Google Reader API（FreshRSS / Tiny Tiny RSS / Miniflux）；同步订阅、文章、已读/收藏；启用后与本地订阅合并保留；账密认证并允许 http/自签证书。

## Overview

让用户接入**自己部署**的 RSS 服务（FreshRSS / TTRSS / Miniflux），在不多端登录第三方云服务、
也不需要本应用自建后端的前提下，实现订阅与阅读状态的跨设备同步。本地数据库仍是离线可读的权威副本，
远端作为收敛目标：在线时双向同步，离线时继续本地操作，恢复网络后自动补发。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 连接自己的 RSS 服务 (Priority: P1)

用户在自己的 NAS / 服务器上跑 FreshRSS，希望 App 连上去，而不是只在本机手工加订阅。

**Why this priority**: 没有可靠的连接与凭据管理，后续同步都无从谈起。

**Independent Test**: 输入服务地址、账号、密码，连接成功后显示服务信息与订阅数；错误输入给出可操作提示。

**Acceptance Scenarios**:

1. **Given** 服务地址正确、账号密码正确、GReader API 已开启，**When** 点击「连接」，**Then** 5 秒内返回成功，并显示远端订阅数量。
2. **Given** 密码错误，**When** 连接，**Then** 提示「账号或密码错误」，不清空已填表单。
3. **Given** 地址不可达或证书不受信任，**When** 连接，**Then** 分别提示网络错误 / 证书错误，并保留「允许 http」开关说明。
4. **Given** 服务端未开启 GReader API，**When** 连接，**Then** 提示「服务未开启 Google Reader API」并给出开启入口说明。
5. **Given** 已连接账号，**When** 打开设置页，**Then** 能看到服务地址、账号、最后同步时间与当前状态。

---

### User Story 2 - 同步订阅与文章 (Priority: P1)

用户希望手机上看到与服务器一致的订阅和文章，新文章不必手动抓取。

**Why this priority**: 这是多端体验的主体价值。

**Independent Test**: 连接后首次同步，远端订阅与文章进入本地；再次同步只拉新增，不产生重复。

**Acceptance Scenarios**:

1. **Given** 本地已有订阅，**When** 连接远端并同步，**Then** 远端订阅按地址合并到本地，本地独有订阅保留。
2. **Given** 远端有 500 篇新文章，**When** 首次同步，**Then** 30 秒内完成，本地列表可见，且与本地已有文章不重复。
3. **Given** 已完成首次同步，**When** 再次同步且远端无新增，**Then** 不产生新文章、不重复插入、耗时明显更短。
4. **Given** 同步过程中网络中断，**When** 恢复网络后再次同步，**Then** 从游标继续，不丢文章、不重复。
5. **Given** 远端删除/停用了某订阅，**When** 同步，**Then** 本地保留该源历史文章并标记为「远端已移除」，不静默删数据。

---

### User Story 3 - 已读 / 收藏双向同步 (Priority: P1)

用户在手机标了已读或收藏，希望服务器和另一台设备也能看到；反之亦然。

**Why this priority**: 状态不同步会让多端体验比单机更糟。

**Independent Test**: 本地标已读/收藏 → 同步 → 远端状态变化；远端改状态 → 同步 → 本地变化。

**Acceptance Scenarios**:

1. **Given** 本地把 50 篇标为已读，**When** 同步，**Then** 5 秒内回写远端，远端已读状态一致。
2. **Given** 远端把某篇标为收藏，**When** 同步，**Then** 本地该篇变为收藏，且不覆盖本地正文/阅读进度。
3. **Given** 同一篇两端状态冲突，**When** 同步，**Then** 按「最近修改优先」收敛，已读/收藏可合并，进度取本地较大值。
4. **Given** 离线时标了已读，**When** 恢复网络并同步，**Then** 待同步队列自动补发，不丢状态。
5. **Given** 回写失败（服务端 5xx / 超时），**When** 下次同步，**Then** 自动重试，失败次数与最后错误可见。

---

### Edge Cases

- 服务地址带/不带 `/api/greader.php` 路径、带尾斜杠、使用 http 或 https。
- 自签证书 / 局域网 IP / 端口非 443。
- 账号里包含特殊字符（邮箱、`+`、非 ASCII）。
- 远端文章没有发布时间、没有作者、正文为空。
- 同一 URL 在远端被两个订阅源收录。
- 本地文章 id 与远端 id 无法一一对应（历史本地文章）。
- 同步过程中应用切后台 / 被杀。
- 退出登录 / 更换账号 / 服务端清空数据。
- 待同步队列积压较多（>1000 条）。
- 服务端限流（429）或临时不可用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持配置一个远端服务（地址、用户名、密码），并支持测试连接。
- **FR-002**: 凭据 MUST 加密存储，MUST NOT 写入日志或明文偏好。
- **FR-003**: 系统 MUST 明确区分连接错误：网络不可达、证书不受信任、凭据错误、API 未开启、服务端错误。
- **FR-004**: 系统 MUST 支持 http 与自签证书（默认给出风险提示，由用户显式允许）。
- **FR-005**: 系统 MUST 通过 Google Reader API 拉取远端订阅列表与分组。
- **FR-006**: 系统 MUST 按订阅地址归一化合并远端与本地订阅，保留本地独有订阅。
- **FR-007**: 系统 MUST 支持增量拉取文章（基于游标 / 时间戳），并保证不重复插入。
- **FR-008**: 系统 MUST 为远端文章建立稳定映射，避免同一文章在本地出现多条。
- **FR-009**: 系统 MUST 将本地已读/收藏变更写入待同步队列，并在同步时批量回写远端。
- **FR-010**: 系统 MUST 拉取远端已读/收藏变更并只更新状态字段，不覆盖正文、阅读进度与标签。
- **FR-011**: 冲突 MUST 按「最近修改优先」收敛；已读/收藏可合并，进度取本地较大值。
- **FR-012**: 系统 MUST 支持手动同步，并可按设置间隔自动同步（回前台 / 后台任务）。
- **FR-013**: 离线时 MUST 保持全部本地功能可用，恢复网络后自动补发队列。
- **FR-014**: 系统 MUST 展示同步状态：最后成功时间、待同步条数、失败次数与最近错误。
- **FR-015**: 系统 MUST 支持退出登录；退出后本地数据默认保留，可显式选择清除。
- **FR-016**: 远端删除订阅时 MUST 保留本地历史，仅标记来源状态，不静默删除文章。
- **FR-017**: 所有新增界面与错误文案 MUST 提供简体中文与英文。
- **FR-018**: 同步失败 MUST 不阻塞阅读、检索与抓取。

### Key Entities *(include if feature involves data)*

- **远端账号（RemoteAccount）**：服务地址、用户名、加密凭据、服务类型、启用状态、最后同步时间。
- **同步游标（SyncCursor）**：文章增量拉取游标 / 时间戳与状态回写游标。
- **文章映射（RemoteArticleMap）**：远端文章标识 ↔ 本地文章 id。
- **待同步变更（SyncOutbox）**：文章 id、变更类型（已读/收藏）、目标状态、产生时间、重试次数。
- **同步状态（SyncStatus）**：最后成功/失败时间、待同步条数、最近错误、连续失败次数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 正常网络下连接成功 < 5 秒；失败时 100% 给出可区分的错误类型。
- **SC-002**: 首次同步 500 篇文章 < 30 秒；二次无新增同步 < 3 秒。
- **SC-003**: 50 条已读/收藏回写 < 5 秒；离线变更在恢复网络后 100% 补发成功。
- **SC-004**: 重复同步 10 次后，文章重复率 0%、状态丢失率 0%。
- **SC-005**: 同步失败不影响本地阅读与检索（失败时仍可正常打开文章）。
- **SC-006**: 退出登录后本地文章与阅读状态 100% 保留（除非用户显式清除）。
- **SC-007**: 凭据在偏好库与日志中均不以明文出现（人工检查 + 日志扫描）。

## Assumptions

- 远端已启用 Google Reader API；FreshRSS 默认路径 `/api/greader.php`，TTRSS / Miniflux 由其自身配置提供。
- 第一版仅支持单账号、账密登录（ClientLogin），不做 OAuth、多账号与 Feedbin / Inoreader。
- 不推送本地新增订阅到远端（只拉取合并）；如需双向订阅管理留到后续批次。
- 不同步标签与稍后读；标签仍是纯本地能力。
- 正文仍由本地提取与缓存，远端只提供标题/摘要/链接/时间/状态。
- 同步是「最终一致」，允许短暂不一致；不提供实时推送。
- 现有纯状态管理 V2、HDS 组件、schema 版本化迁移与构建约束继续有效。
