# Feature Specification: 备份与迁移

**Created**: 2026-10-23
**Status**: Draft
**Input**: `TODO.md` P2-2。用户已确认：全量元数据（不含正文缓存）、合并导入、每日自动快照保留 7 份、文件导出/导入。

## Overview

让用户在换机或重装前把「订阅、阅读状态、高亮、标签、智能文件夹、规则、模板与设置」打包成一个 JSON 文件，
在新设备上一键合并恢复；同时在应用内每日自动生成快照并保留最近 7 份，作为误操作与升级失败后的兜底。
备份不包含正文 HTML、远端账号密码与设备相关路径，体积可控且不泄露凭据。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 导出备份文件 (Priority: P1)

用户要换手机，希望把全部阅读数据带走。

**Why this priority**: 没有导出就没有迁移，这是换机场景的起点。

**Independent Test**: 导出后文件可在文件管理器中看到；文件包含版本号与各数据段；不含密码。

**Acceptance Scenarios**:

1. **Given** 用户有订阅、已读状态、高亮、标签、规则与模板，**When** 点击「导出备份」，**Then** 生成一个 JSON 文件并弹出系统保存位置。
2. **Given** 导出完成，**When** 检查文件内容，**Then** 包含 `version` / `exportedAt` / feeds / articles（元数据）/ highlights / tags / smartFolders / rules / templates / settings 各段。
3. **Given** 用户配置过远端账号，**When** 导出，**Then** 文件中不包含密码、Token 或远端凭据。
4. **Given** 本地有 2 万篇文章，**When** 导出，**Then** 10 秒内完成，文件大小 < 20MB（不含正文缓存）。

---

### User Story 2 - 导入并合并恢复 (Priority: P1)

用户在新设备安装后，希望用备份文件恢复，且不影响已有数据。

**Independent Test**: 导入到空库能完整恢复；导入到已有数据的库只补充缺失项，不覆盖/不删除。

**Acceptance Scenarios**:

1. **Given** 新设备为空库，**When** 选择备份文件导入，**Then** 订阅、文章状态、高亮、标签、智能文件夹、规则、模板全部恢复。
2. **Given** 当前已有部分订阅，**When** 导入同一备份，**Then** 按 URL 去重，不产生重复订阅；已读/收藏取并集。
3. **Given** 同一备份连续导入两次，**When** 第二次完成，**Then** 各表条数不变（幂等）。
4. **Given** 备份包含高亮但对应文章不存在，**When** 导入，**Then** 跳过该高亮并计入「跳过」统计，不报错中断。
5. **Given** 用户在导入前勾选「同时恢复设置」，**When** 导入完成，**Then** 主题/排版/列表/去重等设置按备份应用；未勾选时保留当前设置。
6. **Given** 备份文件损坏或版本不支持，**When** 导入，**Then** 明确提示原因，不修改现有数据。

---

### User Story 3 - 自动快照与恢复 (Priority: P2)

用户误删了订阅或改坏了设置，希望回到昨天的状态。

**Independent Test**: 应用启动后自动生成当日快照；快照列表保留 7 份；可从中恢复。

**Acceptance Scenarios**:

1. **Given** 距上次快照已超过 24 小时，**When** 启动应用，**Then** 后台生成当日快照且不阻塞首屏。
2. **Given** 已连续 8 天生成快照，**When** 查看快照列表，**Then** 只保留最近 7 份，最旧的被清理。
3. **Given** 用户选择一个历史快照并恢复，**When** 完成，**Then** 数据回到该快照状态（合并导入）。
4. **Given** 快照生成失败（磁盘满/权限），**When** 启动应用，**Then** 不弹出阻塞提示，仅记录并在设置页显示状态。

---

### Edge Cases

- 备份文件超大（>50MB）或包含未知字段 → 忽略未知字段，已知字段按版本兼容处理。
- 备份中的文章 feedId 在本地不存在 → 跳过该文章并计数。
- 标签名冲突（大小写不同）→ 按 name_key 合并到已有标签。
- 智能文件夹/规则同名但内容不同 → 按 id 合并；id 不存在时新建。
- 设置中的自定义背景图路径在新设备无效 → 导出时剔除，导入时忽略。
- 导入过程中应用被杀 → 已导入部分保留，下次导入幂等继续。
- 自动快照与手动导入并发 → 串行执行，避免互相覆盖。
- 时区/时钟异常导致快照日期重复 → 同一天只保留一份（覆盖）。
- 空库导出 → 生成仅含版本与空数组的合法文件。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持导出单个 JSON 备份文件（版本化、含导出时间）。
- **FR-002**: 备份 MUST 包含：订阅与分组、文章元数据与阅读状态、高亮、标签及关联、智能文件夹、规则、分享模板、应用设置。
- **FR-003**: 备份 MUST NOT 包含：文章正文 HTML/纯文本缓存、远端账号密码/Token、设备相关文件路径。
- **FR-004**: 系统 MUST 支持通过系统文件选择器导入备份。
- **FR-005**: 导入 MUST 采用合并策略：订阅按 URL、文章按 id、高亮按 id、标签按归一化名称、文章-标签按联合键去重；已读/收藏/稍后读取并集；不删除现有数据。
- **FR-006**: 导入 MUST 幂等：同一文件重复导入后各表条数不增长。
- **FR-007**: 设置仅在用户显式勾选「同时恢复设置」时应用。
- **FR-008**: 导入 MUST 校验版本与结构；失败时给出原因且不修改现有数据。
- **FR-009**: 导入 MUST 统计并展示：新增/跳过/失败数量。
- **FR-010**: 系统 MUST 每 24 小时自动生成一次本地快照，保留最近 7 份，旧快照自动清理。
- **FR-011**: 设置页 MUST 提供快照列表（时间/大小）、恢复、删除与立即备份。
- **FR-012**: 导入/恢复后 MUST 刷新列表、未读数、标签/规则/模板状态。
- **FR-013**: 大文件导入/导出 MUST 不阻塞 UI，并有进度提示。
- **FR-014**: 所有新增界面与错误文案 MUST 提供简体中文与英文。

### Key Entities *(include if feature involves data)*

- **备份文档（BackupDocument）**：版本、导出时间、各数据段。
- **订阅段（feeds）**：URL、标题、站点、分组与单源设置。
- **文章段（articles）**：id、feedId、标题/链接/摘要/作者/时间、状态（已读/收藏/稍后读/进度/隐藏/去重关系）。
- **高亮段（highlights）**：文章 id、引文、备注、颜色、锚点。
- **组织段（tags / articleTags / smartFolders / rules）**。
- **设置段（settings）**：主题、排版、列表、去重、自动刷新等（不含凭据）。
- **快照（Snapshot）**：本地自动备份文件（时间、大小、路径）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 2 万篇文章元数据导出 < 10 秒，文件 < 20MB。
- **SC-002**: 2 万篇导入 < 30 秒，期间 UI 可操作。
- **SC-003**: 空库导入恢复完整率 100%（订阅/状态/高亮/标签/规则/模板）。
- **SC-004**: 同一备份重复导入 3 次，各表条数增量 0。
- **SC-005**: 导入不删除任何现有数据（删除数 0）。
- **SC-006**: 自动快照每天 1 份，保留恰好 7 份（第 8 天清理最旧）。
- **SC-007**: 导出文件中密码/Token 出现次数 0（人工 + 关键字扫描）。

## Assumptions

- 本轮只做文件导出/导入，不做扫码/局域网传输与云盘自动上传。
- 备份不含正文缓存；导入后文章在首次打开时重新提取（与远端同步文章一致）。
- 远端账号需要在新设备重新登录（凭据不备份）。
- 自定义背景图不备份（设备路径无效），导入后回到默认背景。
- 自动快照存应用私有目录，不占用户可见空间；用户可在设置页删除。
- 导入合并以「不丢数据」为优先，不做逐项冲突弹窗。
- 现有纯状态管理 V2、HDS 约束与 schema 版本化迁移继续有效。

## Open Questions
