# Feature Specification: 诊断与性能

**Created**: 2026-10-26
**Status**: Implemented
**Input**: `TODO.md` P2-5。

## Overview

补齐「性能可观测 + 用户可见诊断」：

- 启动到首屏耗时（系统 `launchUTCTime` → 首屏后回调）；
- 逐源抓取耗时、成功 / 失败数、平均每源耗时、最慢的源；
- 抓取失败五类归因（超时 / 网络 / HTTP / 内容解析 / 其他）；
- 列表滚动帧率（`displaySync` 2 秒窗口，30 秒内最多采样一次）；
- 上次退出原因归类（JS / Native / 卡死 / 资源管控 / 正常…），**不拦截异常、不改变崩溃行为**；
- 源健康（连续失败次数 / 最后错误）与一键重试；
- 运行时事实（LazyForEach 分页、数据库索引、本地文章与正文缓存条数）。

全部指标只写本机偏好库；不实现任何上报，也不接入统计 SDK。

## Requirements

- **FR-001**: 启动耗时以系统给的 UIAbility 启动时间为基准，缺失时回退 `onCreate` 时刻；只测一次首屏。
- **FR-002**: 抓取统计按轮聚合，逐源采样；失败按五类归因，不直接向用户摊错误码。
- **FR-003**: 抓取样本上限 500，最慢源只展示前 3；批量异常不占无限内存。
- **FR-004**: 列表帧率采样只在用户开始滚动时启动 2 秒窗口；30 秒内最多一次；关闭诊断后不采样。
- **FR-005**: 崩溃归类只读 `LaunchParam.lastExitReason / lastExitMessage`，不注册 `errorManager.on('error')`，
  不吞异常、不改变系统默认退出行为。
- **FR-006**: 诊断开关默认开启；关闭后不再记录启动 / 抓取 / 帧率指标，上次退出原因仍来自系统。
- **FR-007**: 抓取统计与帧率指标持久化（跨启动可见）；「清除诊断记录」可一键清空。
- **FR-008**: 诊断页可查看失败源并跳转源设置；支持一键重试全部启用源。
- **FR-009**: 不新增权限、不新增网络请求；中英文案齐备。

## Acceptance

- 冷启动后打开「设置 → 系统 → 诊断与性能」，能看到启动到首屏耗时与本次启动时间。
- 完成一次抓取后，页面显示本轮总耗时、成功 / 失败数、五类归因与最慢的三个源。
- 滚动首页后再进入诊断页，能看到平均 FPS 与最差单帧耗时；30 秒内反复滚动不会重复采样。
- 源抓取失败后出现在「源健康」，点击进入源设置，或一键重试全部源。
- 关闭诊断开关后，新一轮抓取不再更新耗时统计；清除按钮可清空已记录数据。
- 上次应用被系统杀死 / 崩溃后重启，页面按系统值显示上次退出原因与详情。
