**Created**: 2026-10-28
**Status**: Done

## Overview

第一批同步内核只支持设置页手动「立即同步」，真机上基本不会被走到。本批把同步接进应用生命周期：
冷启动 / 回前台 / 抓取完成三个时机自动触发，配合节流、失败退避重试与「仅 Wi-Fi」设置，
让同步在不打扰用户的前提下自己收敛。

## Requirements

- **FR-001**: 自动触发点三个 —— 冷启动（`Index.onPageShow`，与回前台同一入口）、
      抓取完成（`FeedViewModel.commitFresh` 收尾）、失败重试；手动「立即同步」保持不变。
- **FR-002**: 节流：距上次成功同步或上次尝试不足 60 秒时跳过；同一时段连续触发只跑一次。
- **FR-003**: 失败重试：自动同步失败后按 30s / 60s / 120s 退避，最多三次；
      用尽后交给下一次自动触发；手动同步成功 / 关闭同步 / 重置远端都会清掉待重试定时器。
- **FR-004**: 仅 Wi-Fi：默认开启；只约束自动同步（含重试），手动同步由用户自行决定。
      判定按默认网络承载类型（`BEARER_WIFI` / `BEARER_ETHERNET` 视为非计费），查询失败按计费处理。
- **FR-005**: 静默跳过：开关关闭、正在同步、仅 Wi-Fi 且当前非 Wi-Fi 时不发起、不提示、不写日志为错误级。
- **FR-006**: 自动同步成功后刷新列表（订阅源可能新增 / 停用，文章状态可能变化），失败静默。
- **FR-007**: 设置页新增「仅 Wi-Fi 同步」开关（默认开），状态快照带 `wifiOnly`。
- **FR-008**: 策略为纯函数（`AutoSyncPolicy`），可脱离数据库单测。

## Acceptance

- 开启同步后冷启动 / 回前台会自动同步一次；60 秒内再次回前台不重复跑。
- 抓取完成后同步自动执行，列表能看到远端带来的新订阅与状态变化。
- 失败时后台按 30s / 60s / 120s 补试三次，用尽后停止；下次触发重新开始。
- 仅 Wi-Fi 开启且当前为蜂窝网络时自动同步跳过，关闭后恢复。
- 关闭同步后不再有任何自动触发，也不残留定时器。

## Out of Scope

- 真实 HTTP 服务端与账号体系。
- 后台任务（WorkScheduler / 卡片）内的同步触发。
- 冲突提示 UI。
