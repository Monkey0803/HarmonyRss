# Feature Specification: 账号与云同步（内容实体第三批）

**Created**: 2026-10-28
**Status**: Done
**Input**: `TODO.md` P0-1 第 1 项剩余部分（高亮 / 标签 / 设置纳入同步模型）

## Overview

前两批只同步订阅源与文章状态，换机后高亮、标签与偏好仍会丢。本批把内容类数据接进同一套
`SyncRecord` 管线：高亮、标签、文章↔标签关联、白名单设置。全部沿用「本地库为权威副本、
先拉后推、墓碑传播」的既有编排，不新增同步表和数据库版本。

## Requirements

- **FR-001**: 新增实体类型 `highlight` / `tag` / `articleTag` / `settings`，全部走记录级后写胜出
      （时间相同按 `origin` 收敛），删除同样用墓碑。
- **FR-002**: 高亮键 `highlight:<id>`，载荷含文章 id、引文、备注、配色、创建时间与定位锚点；
      文章不存在时应用跳过（等文章入库后下次同步再补）。
- **FR-003**: 标签键 `tag:<归一化名称小写>`，载荷只有展示名与创建时间 —— 两端同名标签自动收敛成一条，
      不依赖本地生成的 tag id。
- **FR-004**: 文章↔标签关联键 `articleTag:<归一化名称>|<文章 id>`，应用时按名称解析本地 tag id、
      按文章 id 检查存在性；标签记录尚未落地的关联先跳过。
- **FR-005**: 设置用单条记录 `setting:app`，载荷是白名单键的扁平 JSON（复用备份白名单）；
      只在白名单键真的变化时才写回并应用主题 / 语言副作用。
- **FR-006**: 差量采集对比「当前快照 payload ↔ 同步表 payload」，相同则保持时间戳不变（不制造假脏）。
- **FR-007**: 设置不产生墓碑（缺键视为未同步，而不是删除），避免旧版本客户端误删新设置。
- **FR-008**: 智能文件夹键 `smartFolder:<归一化名称>`，载荷为名称 + 检索语法；排序位是设备本地偏好，不同步。
- **FR-009**: 规则键 `rule:<归一化名称>`，载荷含名称 / 开关 / 关键词 / 字段 / 动作；订阅源与标签引用
      分别换成**归一化 URL** 与**归一化名称**再同步；优先级与命中统计属本机执行状态，不进载荷
      （否则每轮都会判脏）。数组排序后再编码，避免顺序差异导致来回覆盖。
- **FR-010**: 分享模板键 `template:<归一化名称>`，载荷为名称 + 正文；内置默认模板未落库，不参与同步。

## Acceptance

- 在 A 端新增高亮 / 备注 / 配色、创建标签并给文章打标、改主题，同步后 B 端（Mock 已连通）同步一次即可看到。
- 删除高亮 / 取消标签关联 / 删除标签同样传播到另一端。
- 两端各自创建同名标签（大小写不同）后同步，最终只有一条标签。
- 本地没有该文章时，高亮与关联先保留记录不报错；文章入库后下一次同步补齐。
- 智能文件夹 / 规则 / 分享模板在 A 端新建或编辑后，B 端同步一次即可看到，改名表现为「旧名消失 + 新名出现」。
- 规则里的来源范围与打标签动作在 B 端仍指向正确的订阅源与标签（引用按 URL / 名称解析）。

## Out of Scope

- 真实 HTTP 服务端与账号体系。
- 高亮 / 标签的阶段性合并（改同一高亮的两端仍按后写胜出）。
- 规则优先级与命中统计的跨设备同步。
